# Limitations, module by module and day by day

Moved from the README on 25 Oct 2026 so the README leads with the verdict; the general limitations stay in the README. Every bullet is kept exactly as it was.

- The v0.7 valuation gate (`stockstalker.gates.valuation`) reads reverse-dcf-engine's contract for Gulf Oil Lubricants India (GULFOILLUB), a name that is not in this repo's 3-ticker fixture universe (RELIANCE, TATACHEM, CROMPTON). Running the real integration end to end today produces zero matches — the gate logic is exercised by tests against a synthetic contract keyed to a universe ticker, but no genuine valuation figure has actually been attached to a live candidate yet. That happens only once the two repos' universes overlap, or a satellite is re-run against a shared ticker.
- The v0.3 risk gate (`stockstalker.gates.risk`) reads monte-carlo-risk-lab's VaR/CVaR contract for RELIANCE, which *is* in this repo's universe, so `--risk-contract fixtures/risk/RELIANCE.json --risk-ticker RELIANCE` genuinely attaches to a live candidate rather than matching a synthetic stand-in. But the contract itself is only as good as monte-carlo-risk-lab's own model: that repo's README records that its Kupiec backtest rejects the 1-day parametric VaR at the 99% confidence level on this exact fixture (thin GBM tails understate real exceptions), and `var_95`/`cvar_95` here come from its historical (non-parametric) method specifically to avoid inheriting that failure — but the 99% figure was not in this contract at all until fix-phase Day 6. Fix-phase Day 5 added a one-line Kupiec caveat to the front door's console output and tear sheet (see `stockstalker.gates.risk.KUPIEC_NOTES`) so a reader no longer has to go read that repo directly to learn the 99% backtest fails here. **Superseded, fix-phase Day 6 (R5):** the contract file itself now carries `var_99`/`cvar_99` and the full `kupiec_95`/`kupiec_99` Kupiec backtest (`fixtures/risk/RELIANCE.json` regenerated by monte-carlo-risk-lab's own `mcsim.portfolio --contract`), so the 99%/Kupiec verdict is a real field in the contract, not just a caveat sourced to another repo's README. `kupiec_note` now computes its one-line summary from those real fields (`stockstalker.gates.risk._kupiec_verdict_note`) instead of the hardcoded `KUPIEC_NOTES` table, which is kept only as a fallback for a contract that hasn't been regenerated.
- The v0.2 factor gate (`stockstalker.gates.factor`) reads fama-french-factor-model's FF5+momentum contract for RELIANCE — another genuine match, like v0.3's, not a synthetic stand-in. But the underlying regression is underpowered by that repo's own account: only 22 months overlap between this repo's OHLCV fixture window and Ken French's factor fixture, not enough to estimate up to seven parameters with any confidence, and it regresses INR closing prices against USD-denominated factors with no currency adjustment. All three of this repo's candidates come back with `significant: false` under every model that repo ran (plain-OLS and Newey-West alike) — read that as "underpowered," not as "the screen's edge is proven to be beta in disguise." See that repo's own README for the full caveat list. Fix-phase Day 5 labels this specific contract "old method" wherever it is shown (`stockstalker.gates.factor.OLD_METHOD_FACTOR_TICKERS`) — GULFOILLUB's own factor section (below) uses IIMA's Indian factors instead and carries no such label.
- The v0.4 sizing gate (`stockstalker.gates.sizing`) reads markowitz-portfolio-optimizer's contract for RELIANCE.NS — a genuine match, like v0.3's and v0.2's, since that repo built its own fixtures from this repo's committed OHLCV history. But the number attached is not a diversified allocation: that repo's raw unconstrained max-Sharpe tangency portfolio on its 3-name universe is a 100% RELIANCE.NS corner solution, so the contract instead reports a sector-capped solve (50% cap) — RELIANCE.NS gets exactly 50%, with its own single-member sector ("Energy") as the binding constraint. Every ticker in that universe sits in its own sector, so the cap is mathematically identical to a plain position limit on RELIANCE.NS alone, not a genuine multi-name diversification constraint. And a less flattering number from that repo's own README: the sector-capped portfolio's Sharpe ratio is *worse* than the uncapped one (-0.83 vs -0.30) — forcing this "diversification" made risk-adjusted return worse, not better, on this fixture set. Read the 50% weight as one candidate's sizing gate output, not a recommended real-money allocation.
- The v0.5 sentiment gate (`stockstalker.gates.sentiment`) reads headline-sentiment-vs-price's contract for INFY.NS (Infosys), which is not in this repo's 3-ticker fixture universe (RELIANCE, TATACHEM, CROMPTON) — like v0.7's GULFOILLUB, not like v0.3/v0.2/v0.4/v0.6's genuine RELIANCE matches. Running the real integration end to end today produces zero matches — the gate logic is exercised by tests against a synthetic contract keyed to a universe ticker, but no genuine sentiment score has actually been attached to a live candidate yet. The contract itself also ships `"model": "vader"` rather than the `"finbert"` NEXT_STEPS.md originally envisioned, because that repo's sandbox has no `torch` installed; read any `score_7d` this gate attaches as a general-purpose lexicon score, not a finance-tuned one, until that repo's FinBERT path is actually exercised somewhere with network access and a cached model.
- The v0.8 fundamentals gate (`stockstalker.gates.fundamentals`) reads three-statement-model's contract for Gulf Oil Lubricants India (GULFOILLUB) — the same name v0.7's valuation gate already reads, since both satellites research the same company. GULFOILLUB is not in this repo's 3-ticker fixture universe (RELIANCE, TATACHEM, CROMPTON), so, like v0.7's and v0.5's integrations, the real end-to-end run produces zero matches; the gate logic is exercised by tests against a synthetic contract keyed to a universe ticker instead. The contract itself is real, not a placeholder: `fy3_revenue_cagr` (+15.39%), `fy3_ebit_margin` (12.82%) and `net_debt_ebitda_fy3` (-1.69, a net-cash position) come from that repo's actual 3-year linkage forecast on GULFOILLUB's real historical financials, and `balance_check` only reads `"passed"` because that repo's own balance-sheet assertion genuinely passed for every forecast year — it is not hardcoded.
- The front door's contract sections (`stockstalker.run.build_contract_sections`) read each gate's `load_contract` directly against `fixtures/<namespace>/<TICKER>.json` for the subject ticker, bypassing the screen-gate pattern above entirely (that pattern only matches a ticker already in `data/universe.txt`, which the subject deliberately is not). As of Day 5, that gives four real, filled sections for GULFOILLUB — `valuation` (reverse-dcf-engine), `fundamentals` (three-statement-model), `risk` (monte-carlo-risk-lab, whose `mcsim.portfolio` was re-run against a copied-in GULFOILLUB fixture rather than RELIANCE's) and `factor` (fama-french-factor-model, regressed against IIMA's Indian factors rather than RELIANCE's Ken French ones) — and two honest "not available" lines for `vol` and `sentiment`, whose committed fixtures are still keyed to RELIANCE/INFY from earlier integrations. Those two fill in only once their own repos write a `GULFOILLUB.json` fixture, on NEXT_STEPS.md's Day 6. `sizing` is left out of the front door on purpose, not because of a missing fixture: markowitz-portfolio-optimizer's sector-capped weight is only meaningful across a screened universe of candidates competing for the same capital, and a sector cap across the subject plus its three lubricant peers would be a sector bet dressed up as a position size.
- GULFOILLUB's real `risk` section (Day 3) is a worse Kupiec result than RELIANCE's own v0.3 integration: the parametric 1-day VaR is rejected at both 95% and 99% confidence on GULFOILLUB's ~11-year fixture, where RELIANCE's ~2-year fixture only failed at 99%. The front door renders the four original risk numbers (`var_95`, `cvar_95`, `max_dd_sim`, `horizon_days`) plus, as of fix-phase Day 5, a one-line Kupiec caveat underneath stating the rejection outright — a reader relying only on this tear sheet can now see that the model backing those numbers is rejected at both confidence levels without going to monte-carlo-risk-lab's own README. **Superseded, fix-phase Day 6 (R5):** the contract JSON itself now also carries `var_99`, `cvar_99`, `kupiec_95` and `kupiec_99` (regenerated `fixtures/risk/GULFOILLUB.json`), so the front door renders all eight fields and the Kupiec caveat underneath is now computed from those real fields rather than sourced to another repo's README.
- GULFOILLUB's real `factor` section (Day 5) is a genuinely different regression from RELIANCE's screen-gate one, not just a different ticker: 137 overlapping months against RELIANCE's underpowered 22, IIMA's Indian factors instead of Ken French's USD ones, and FF3+WML instead of FF5+Mom (IIMA has no RMW/CMA). The honest result is still an insignificant alpha (`alpha_t` ≈ +1.01, OLS) despite the much larger sample — the front door renders `alpha_annual`, `alpha_t`, `significant` and the `loadings` dict (including a `wml` key RELIANCE's own FF5+Mom contract has never carried) but not the Newey-West-corrected t-stat or the diagnostics tests fama-french-factor-model's own README records; a reader who needs those has to go read that repo directly, the same gap the `risk` section above already has for its Kupiec verdict.
- Day 6 is an absence day, and both absences are real, not placeholders. `sentiment` is now filled for GULFOILLUB with a genuine zero: `python -m sentiment.contract --ticker GULFOILLUB.NS` against headline-sentiment-vs-price's ~50-headline Economic Times RSS snapshot returns `{"score_7d": null, "headline_count_7d": 0, "model": "vader", "coverage": "none"}`, because that repo's ticker table (`sentiment.tickers`) has no rule naming GULFOILLUB at all — a deliberately narrow, closed lookup (see that repo's README), not a filter that happened to exclude it. A count of zero from a ~50-headline single-source snapshot says nothing about this stock's real news coverage; it is a fact about the corpus, not about the company. `vol` stayed unavailable through Day 6, and the reason then was an investigated "unverified": a live check against NSE's own option-chain endpoint (`volsurface.chain.NSEChainProvider`) was run from this sandbox for both GULFOILLUB and RELIANCE, and both came back with the identical empty `{}` payload after a 403 on the cookie warm-up — RELIANCE is known to have listed NSE options, so an empty response proved the sandbox's network was blocked, not that GULFOILLUB has no option chain. **Superseded, fix-phase Day 5 (D2):** NSE's own F&O lot-size snapshot (`fixtures/fo_mktlots.csv`, fetched directly — this sandbox's network reached NSE fine this time) settles the question without the option-chain endpoint at all: GULFOILLUB's SYMBOL is genuinely absent from that list, so the reason is now "no listed options: not an NSE F&O underlying," a checked fact rather than a network-blocked hedge (`stockstalker.run.load_fo_underlyings`/`_vol_unavailable_reason`, replacing the old `UNVERIFIED_CONTRACT_REASONS` mechanism). The same check applies to any ticker, not just GULFOILLUB — e.g. the lubricant peer CASTROLIND is equally absent from the list and gets the same message.
- Day 7's three charts (`stockstalker.viz.charts`, written to `outputs/` by `stockstalker.run` unless `--no-charts`) are deliberately scoped narrower than "subject vs peers" everywhere: only the rebased comparison plots all four names, because NEXT_STEPS.md's "subject vs peers" qualifier sits on that one chart alone — drawdown and rolling volatility are GULFOILLUB only, a risk profile of the name the note is about, not a four-line reprise of the peer table. The rebased comparison is not one shared start date either: each series is divided by its own first close, so CASTROLIND and SOTL (both committed back to 2014-07-31, the same day as GULFOILLUB) rebase from day one of the subject's own history, but GANDHAR (IPO 2023-11-30) rebases from its own much later first day — the legend names each series' own start date so a ~3-year GANDHAR line is never misread as spanning the same ~11 years as the other three. These fixtures were pulled with `yfinance`'s `auto_adjust=True`, which already folds dividends into every close, so these are rebased total-return-ish series, not pure price.
- Day 8's trading costs (`backtest.STT_RATE`, `backtest.STAMP_DUTY_RATE`, `--slippage-bps`) are a flat percentage of position value charged on each entry and exit, not a simulated order-book fill. There is no separate bid-ask spread, no market-impact model, and no partial fills — real execution on ~140-190 round trips a year on these small/mid-cap names would plausibly be worse, not better, than this estimate. `stockstalker.report`'s backtest table still shows only the no-cost numbers (it calls the same `run_backtest`, but renders `strategy_return`/`buy_and_hold_return`, not the `_with_costs` fields) — the cost-adjusted view only exists in this README's Findings section and in `outputs/backtest_<date>.{json,csv,md}`, not in the quick terminal screen.
- Day 9 is a documentation day, not a code day — no module in `stockstalker/` changed. It corrects a framing error this README carried since Day 1 of the front-door project (and, before that, every earlier checkpoint note): calling the screen "the funnel" that narrows a universe down to the pipeline's one subject. That was never what happened. GULFOILLUB was chosen by hand in `reverse-dcf-engine/research/shortlist.md` against written criteria, and the screen's own 3-ticker universe (RELIANCE, TATACHEM, CROMPTON) has no overlap with it at all — a reader who took the old wording literally would have incorrectly concluded the screen ran over a larger universe at some point and produced GULFOILLUB as its output. It did not. This correction does not change any number in this README; it changes what the numbers are claimed to be downstream of.
- **Fix-phase Day 5 (CRITIQUES.md D2, R5, R6, R7) — front-door honesty.** `fixtures/fo_mktlots.csv` (NSE's own current F&O lot-size snapshot, fetched 2026-10-17, list dated 2026-09-29 per its Last-Modified header; `fixtures/fo_mktlots_meta.json` records the capture) replaces the old GULFOILLUB-only `UNVERIFIED_CONTRACT_REASONS` special case with a real membership check any ticker goes through (D2, see the amended `vol` bullets above). The `risk` and `factor` sections each gained a one-line sourced caveat printed to both the console and the tear sheet — the Kupiec 99% rejection for `risk` (R5), and the old-Ken-French-method label for `factor` on RELIANCE's contract specifically (R6) — and the `factor` contract's `significant` field now renders as the words "significant"/"not significant" rather than a bare `True`/`False` (R6). The `sizing`-exclusion rationale (R7, already true and already in the tear sheet since Day 2) now also prints to the console, not just the markdown file. None of this changes a single number any contract carries; it only states, next to each number, what that number does and does not mean — the actual 99%/Kupiec figures still only live in monte-carlo-risk-lab's own README until Day 6 adds them to the contract itself.
- **Fix-phase Day 25 (CRITIQUES.md C1, S10) — the any-stock claim, verified, not just coded.** Days 20–24 built `--live` support for a ticker outside GULFOILLUB's own fixtures, but nobody had actually run it against a non-lubricant, F&O-listed name before this day. `python -m stockstalker.run --ticker <TICKER> --live --no-charts` was run end to end for three real tickers and every tear sheet committed as evidence at `verification/tearsheets/`: RELIANCE (F&O large-cap — `risk`, `factor` and `vol` render from their own already-committed fixtures; `valuation` and `sentiment` generate live, since neither has one), CASTROLIND (non-F&O mid-cap with no committed fixture in any namespace — `valuation`, `risk`, `factor` and `sentiment` all generate live, and `vol` correctly prints "no listed options: not an NSE F&O underlying" rather than a generic "fixture not found"), and GULFOILLUB (`--offline`, the original hand-researched fixtures, unchanged). Every section printed a real number or a specific one-line reason on all three runs — never a placeholder, never a crash. `price_reachable` is `False` for all three under the reverse DCF (method output only, per S5 — no view on whether any of the three is mispriced), and `fundamentals` is unavailable for RELIANCE and CASTROLIND by design, printing `FUNDAMENTALS_SCOPE_NOTE` instead of a fabricated section, since three-statement-model stays driver-based for GULFOILLUB only. This is the verification the front-door paragraph above and the site's StockStalker paragraph now describe (S10: never claim more than a verified run shows).
